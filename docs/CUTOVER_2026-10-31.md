# Car Doc Final Cutover — October 31, 2026

This runbook is for the Windows/Shopman32 → PlumWorks production cutover after business close on **Saturday, October 31, 2026**. Windows remains authoritative through October 31. PlumWorks becomes authoritative on **Sunday, November 1, 2026**.

## Final-state rule

The production app must start November 1 with **real configuration preserved but UAT/runtime activity cleared**.

Preserve:

- shop identity/contact information
- tax, labor and shop-supplies settings
- users, memberships and staff invites
- canned services and vendors
- website pages/services/photos/reviews/coupons/settings
- lead notification configuration and recipient emails
- invoice footer, warranty, authorization and certification text
- Michigan repair-facility/technician configuration
- other business configuration required for normal operation

Clear before the Windows reload:

- marketing leads
- lead notifications
- lead notification read state
- public lead anti-spam/submission ledger
- authorization requests
- authorization events
- signature evidence
- document revisions created during UAT
- normal UAT operational data (customers, vehicles, ROs, invoices, payments, AR and legacy staging), which the existing Windows replacement already resets/reloads

The final imported Windows customers/invoices/open ROs are **not** considered UAT data; they are the production starting dataset.

## Non-negotiable gates

Do not proceed unless every gate passes.

1. UAT is approved and the intended production application/schema version is frozen.
2. No Production data mutation occurs during readiness work before the approved cutover window.
3. Final Windows snapshot is taken only after October 31 activity is complete.
4. Snapshot manifest/fingerprint validation passes.
5. Snapshot-bound customer recovery and active-RO adjudication/resolution artifacts are current when required.
6. Cutover dry-run/preflight reports zero blocking issues.
7. A full public-schema backup is created and verified **before any fresh-slate deletion**.
8. Preserved business configuration is captured.
9. Fresh-slate cleanup completes and verifies all targeted UAT/runtime tables are zero.
10. Existing Windows operational reset/reload completes.
11. Post-load row counts, mileage, vendor, complimentary labor, payment, AR, RLS and accounting checks pass.
12. Preserved configuration verifies unchanged.
13. October 2026 report parity passes exactly, including tender/payment totals.
14. Every historical calendar-year report in Windows passes exact parity.
15. 2026 YTD through October 31 passes exact parity.
16. November 1 owner-facing validation passes before normal PlumWorks entry begins.

Any failure is a **NO-GO**.

## Before Saturday

Run the cutover regression tests and rehearse against DEV/staging with a recent Windows snapshot. Do not replace Production while UAT remains active.

## Saturday October 31 — final source freeze

After the shop closes and all October activity is entered in Windows:

1. Stop further Windows entry.
2. Capture the complete final Shopman32 source.
3. Run immutable snapshot intake and retain checksums/manifest.
4. Regenerate or revalidate recovery/adjudication artifacts when the fingerprint changed.
5. Save the final Windows October 2026 report, 2026 YTD report, and representative prior-year reports as control evidence.

Use that exact immutable snapshot for every following step.

## 1. Final read-only preflight

Run the existing cutover preflight against the final snapshot with the exact recovery/adjudication/resolution artifacts it requires.

Required result: no critical issues, no projected count inconsistencies, zero database writes.

## 2. Preview the fresh-slate cleanup

This command is read-only without the confirmation value:

```bash
npm run legacy:cutover:fresh-slate
```

It reports the number of rows that would be cleared from:

- `marketing_leads`
- `marketing_lead_notifications`
- `marketing_lead_notification_reads`
- `public_lead_submissions`
- `authorization_requests`
- `authorization_events`
- `signature_evidence`
- `document_revisions`

Review the counts. These are expected UAT/runtime records and will not be carried into November 1.

## 3. Capture preserved configuration

```bash
node --env-file=.env.local scripts/final-cutover-preserved-state.mjs capture \
  --file reports/cutover-2026-10-31-preserved-state.json
```

This snapshot intentionally excludes leads and UAT authorization evidence because those are supposed to be deleted. It protects business configuration only.

## 4. Create and verify a pre-cleanup backup

Before deleting fresh-slate data, create and verify a full public-schema backup using the existing backup tooling. Retain this backup as the authoritative pre-cutover rollback point.

Do **not** perform fresh-slate deletion until this backup is confirmed valid.

## 5. Clear UAT/runtime data

Only in the approved cutover window:

```bash
npm run legacy:cutover:fresh-slate -- \
  --confirm CLEAR_UAT_RUNTIME_DATA
```

Required result:

```text
Final cutover fresh-slate cleanup: PASS
```

The script performs the deletion transactionally and then recounts every targeted table. All must equal zero.

Website content, shop settings, users, canned services, vendors and notification configuration are not deleted.

## 6. Run the confirmed Windows operational replacement

Run the normal final-production cutover using the final snapshot and the same approved artifacts. Keep its built-in `--backup --verify --report` flags as a second safety layer.

The confirmed cutover still replaces UAT operational customers/vehicles/ROs/invoices/payments/AR with the authoritative Windows data and imports final active ROs.

## 7. Verify configuration preservation

Immediately after reload:

```bash
node --env-file=.env.local scripts/final-cutover-preserved-state.mjs verify \
  --file reports/cutover-2026-10-31-preserved-state.json
```

Required result:

```text
Preserved configuration verification: PASS
```

## 8. Verify the fresh slate remains clean

Run the preview again:

```bash
npm run legacy:cutover:fresh-slate
```

All lead/UAT-evidence counts must remain **0** after the Windows import.

## 9. Mandatory report parity

Run:

```bash
npm run legacy:cutover:final-report-parity -- \
  --source <FINAL_SNAPSHOT_DIR>
```

The gate compares final Windows source data with PlumWorks for:

- October 1–31, 2026
- every complete historical calendar year present in Windows
- 2026 YTD through October 31

It checks invoice counts; parts; labor; subtotal; shop supplies; sales tax; discounts/reductions; legacy charges; gross sales; invoice paid totals; payment-row counts; paid invoices; split tenders; cash; check; card; internal; other; and total payments.

Any one-cent mismatch is a NO-GO.

## November 1 validation

Before the owner enters normal PlumWorks transactions:

1. Confirm Leads shows **0** records and no old notification badge/history appears.
2. Confirm no UAT authorization/signature evidence appears on imported production records.
3. Open Reports → Monthly → October 2026 and compare with the saved Windows month-end report.
4. Open Reports → Yearly → 2026 and compare with the saved Windows YTD report before any November transaction is entered.
5. Spot-check prior-year report totals.
6. Spot-check October 31 invoices, mileage, Source = Legacy, vehicle history, AR/payment state and final active ROs.
7. Run the Production health/smoke check.

Only after these checks pass should the business cutover be accepted.

## Rollback / NO-GO rule

If any confirmed deletion or reload fails, do not make ad-hoc Production edits. Stop PlumWorks transaction entry, retain logs/reports, and recover from the verified pre-cleanup/pre-cutover backup as appropriate. Windows remains authoritative until a clean rerun passes every gate.
